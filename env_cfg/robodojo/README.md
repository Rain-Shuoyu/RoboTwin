# RoboDojo 九项刚体任务的 RoboTwin 移植

本目录保存固定来源的任务身份、原始小型配置和抽取后的成功条件。任务物体、关节和随机杂物在 RoboTwin 中真实加载；机器人、相机和动作执行沿用当前双 Franka。没有专家动作、物体传送或替代成功条件。

来源固定为 RoboDojo 提交 `f57e1633ffed59761bc8e568cfe7530c4b33381c`，资产版本为 `269457a3b42d8d0ae69898a601f2c1487c2f826e`。源代码采用本目录附带的 MIT 许可。此移植改变了仿真器、机器人与桌面高度，结果必须作为移植版本记录，不能称为原排行榜复现。

## 文件与原始判定

- `task_definitions.json` 保存九个准确任务名称、原始任务文件、类名和原步数身份。
- `task_rules.py` 从固定来源的九个任务中抽取 `run_reward`、被直接或间接调用的小型方法及类常量，并从 `env/reward_manager/reward_manager.py` 抽取相应判定构造函数。没有保留原仿真器导入、任务初始化、专家动作或其它执行代码。
- `source_layout_labels.json` 从九份真实预采样布局的第零项提取物体标签、类别和随机杂物数量，供测试核对规则引用，不能作为运行时布局替代。
- `source_config/*.yml` 是固定来源的九份准确原配置（含四项 `_random` 配置），只供来源核对；运行使用已经预采样并离线准备的布局，不重新随机采样。
- `envs/utils/robodojo_predicates.py` 保留 `env/reward_manager/func_parser.py` 中需要的 26 个方法和 `utils/transformer.py` 的必要几何函数，只把状态读取接到当前真实物理物体。计算使用原来的凸包、严格包含、带容差覆盖、方向夹角、功能点、关节比例与初态差值。

外层成功列表要求全部成立；每一项若是列表，按源 `RewardManager.check_once` 在“任一成立”和“全部成立”之间逐层交替。检查顺序与短路行为保留；`organize_table` 的位置稳定检查仍按每次检查更新前态。任务第一次满足原始成功阶段后保持已完成，与原管理器移除已完成阶段一致。缺失所需物体、边界顶点、功能点、链接或关节会留下具体读取错误；不能据模型声称完成替代判定。

工具箱没有关盖条件，钥匙任务没有锁芯关节，整理桌面没有新增抽屉开关条件。蛋托使用盖铰链的原比例阈值。烤面包机保留四片面包，两片分别入槽、两片留在架上、四片方向检查、拨杆关节比例及机器人回位条件。四项随机任务分别读取准确的原始随机版本：随机扫块检查 `target` 前缀下的全部目标；随机烤面包的相对高度范围为 −0.05 米至 0.068 米，不能沿用普通版的 0.03 米至 0.065 米。随机装箱和随机挂杯所需成功条件与对应普通版一致。

## 运行入口与布局身份

原生类统一为 `envs.robodojo_rigid.robodojo_rigid`，`setup_demo` 接收：

```python
task_parameters={"source_task": "insert_key", "source_seed": 0}
```

其它初始化参数沿用当前原生环境。整数 `seed` 就是预采样布局编号，不取模、不换起点。资产根目录由 `ROBOTWIN_ROBODOJO_ASSET_ROOT` 指定，默认是当前 RoboTwin 源码下的 `assets/objects/robodojo_rigid`。实际读取：

```text
<资产根>/layouts/<source_seed>/<source_task>_<seed>.json
<资产根>/assets/<Rigid|Geometry|Articulation|Clutter>/<category>/<五位编号>/asset.json
```

资产与布局必须事先通过独立准备工具保存。服务启动、重置和判定不下载、转换或遍历检查资源；实际读取失败直接保留错误。原布局的物体与随机杂物全部保留，只跳过被当前相机替代的 `camera_stand`。原 `Rigid` 层中 `type: cluttered` 的实例从独立 `Clutter` 资产路径读取，避免与普通刚体同类别、同编号的资源冲突。

九项任务共用一次桌面适配：用当前原生桌面构造函数保留原布局桌面的长宽、厚度和水平中心，默认是 1.4 米 × 1.1 米、中心 `[0, -0.05]`。桌面顶面从原来的 0.765 米移到当前的 0.74 米；全部物体和判定中的绝对高度统一平移 −0.025 米。如果调用者显式使用当前原生桌面高度偏移，同一偏移也作用于全部物体和绝对高度判定。墙统一位于桌面后缘，避免侵入原布局。机器人基座不随桌面改变。原房间、地面和背景由当前原生环境替代。

## 验证边界

`simulation/tests/test_robodojo_tasks.py` 用构造状态覆盖九项原始任务的成功、失败、几何边界、嵌套列表、真实关节读取接口和准确布局编号。构造状态仅证明规则与接口；不能证明物理可操作性、稳定性、双臂可达性或机器人已完成任务。真实物理验证须使用预选原始布局、准备后的完整资产和当前正式动作入口。
